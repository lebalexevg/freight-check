# Руководство разработчика и регламент контрибьюции

> Документ регламентирует настройку рабочего окружения, процесс контроля качества, правила работы с ветками Git и формат сообщений коммитов.

---

## 1. Требования и настройка локального окружения

### 1.1. Системные требования
- **Python:** 3.13
- **Менеджер пакетов:** [`uv`](https://github.com/astral-sh/uv)
- **Менеджер среды и инструментов (рекомендуется при наличии):** [`mise`](https://mise.jdx.dev)
- **ОС:** 64-битные версии Windows 10/11 или Linux x86_64

Проект поддерживает два равноправных способа управления инструментами:
1. **Через `mise` (предпочтительно):** если в вашей системе установлен `mise`, он автоматически использует конфигурацию [`mise.toml`](../mise.toml), фиксируя версии Python 3.13 и uv, а также предоставляя шорткаты задач `mise run <task>`.
2. **Нативно через `uv`:** если вы предпочитаете работать без `mise`, все операции штатно выполняются стандартными командами `uv sync` и `uv run ...`.

### 1.2. Пошаговая инициализация проекта

#### Способ 1: С использованием `mise` (при наличии)
```bash
# 1. Клонирование репозитория
git clone <repo-url>
cd freight-check

# 2. Установка версий инструментов из mise.toml
mise install

# 3. Синхронизация зависимостей виртуального окружения
mise run sync

# 4. Активация pre-commit хуков
mise exec -- uv run pre-commit install
```

#### Способ 2: Нативно через `uv`
```bash
# 1. Клонирование репозитория
git clone <repo-url>
cd freight-check

# 2. Установка зависимостей и синхронизация виртуального окружения
uv sync

# 3. Активация pre-commit хуков
uv run pre-commit install
```

## 2. Команды разработки и контроля качества

Все инструменты запускаются либо через задачи `mise run <task>` (если используется `mise`), либо напрямую через `uv run`:

| Операция | С использованием mise | Нативно через uv |
| :--- | :--- | :--- |
| **Комплексный контроль (lint + types + test)** | `mise run check` | — *(запуск по цепочке)* |
| **Проверка стиля и линтинг (Ruff)** | `mise run lint` | `uv run ruff check` |
| **Автоисправление замечаний Ruff** | `mise run lint:fix` | `uv run ruff check --fix` |
| **Форматирование кода (Ruff)** | `mise run format` | `uv run ruff format` |
| **Проверка форматирования без изменений** | `mise run format:check` | `uv run ruff format --check` |
| **Статическая проверка типов (basedpyright)**| `mise run typecheck` | `uv run basedpyright` |
| **Запуск модульных тестов (pytest)** | `mise run test` | `uv run pytest` |
| **Запуск тестов с подробным выводом** | `mise run test:v` | `uv run pytest -v` |
| **Прогон хуков pre-commit по всем файлам** | `mise run pre-commit` | `uv run pre-commit run --all-files` |
| **Запуск приложения в режиме разработки** | `mise run dev` | `uv run freight-check` |
| **Сборка дистрибутива (PyInstaller)** | `mise run build` | `uv run python scripts/build.py` |
| **Сборщик в Windows PowerShell** | `.\build.ps1` | `.\build.ps1` |

## 3. Регламент работы с Git

1. **Ветка `main` священна:** Прямые коммиты в ветку `main` категорически запрещены.
2. **Ветки задач:** Вся разработка ведется в тематических ветках:
   - `feature/<название>` — для новой функциональности;
   - `bugfix/<название>` — для исправления ошибок.
3. **Слияние изменений:** Слияние в `main` происходит исключительно через Pull Request после:
   - успешного прохождения всех автоматических проверок;
   - обязательного код-ревью минимум одним участником команды.

## 4. Соглашения о коммитах

Все сообщения коммитов должны строго следовать формату:

```text
<тип>(<область>): <описание с маленькой буквы в повелительном наклонении>
```

### 4.1. Разрешенные типы
- `feat` — новая функциональность или парсер;
- `fix` — исправление бага или ошибки сопоставления и нормализации;
- `test` — добавление или модификация тестов;
- `refactor` — изменение структуры кода без изменения его поведения;
- `perf` — оптимизация производительности или потребления памяти;
- `chore` — рутинные задачи, обновление зависимостей;
- `ci` — настройка пайплайнов и проверок;
- `docs` — обновление документации и спецификаций.

### 4.2. Разрешенные области
- `contracts` — модели данных и перечисления: `src/freight_check/contracts.py`;
- `ui` — экраны PySide6, виджеты, стили QSS, потоки `QThread`;
- `parsers` — прямое чтение файлов XML, XLSX, XLS, CSV, DOCX, текстовый PDF;
- `ocr` — конвейер растеризации pypdfium2, OpenCV и распознавания RapidOCR;
- `extract` — семантическое извлечение сущностей и поиск якорных маркеров;
- `norm` — алгоритмы нормализации: госномера ГОСТ, вес, адреса;
- `matcher` — движок сопоставления, бизнес-правила и весовой баланс;
- `pack` — сборка дистрибутива: PyInstaller, Inno Setup;
- `infra` — настройки проекта: `pyproject.toml`, `mise.toml`, uv, pre-commit, gitignore.

### 4.3. Примеры правильных сообщений
- `feat(ui): добавить таблицу расхождений с цветовой индикацией`
- `feat(parsers): добавить извлечение таблиц через openpyxl`
- `feat(extract): реализовать поиск якорных маркеров грузополучателя`
- `fix(norm): исправить парсинг дробного веса с разделителем-запятой`
- `fix(matcher): скорректировать посимвольную проверку номеров строений`
- `test(matcher): добавить тесты для проверки перегруза автомобиля`
- `docs(specs): обновить описание конвейера OCR в architecture.md`
- `feat(infra): настроить конфигурацию mise и шорткаты задач`

## 5. Стандарты кода и линтинг

- **Длина строки:** не более 100 символов.
- **Стиль кавычек:** двойные кавычки.
- **Правила линтера Ruff:**
  - `E`, `W` — базовые ошибки и предупреждения стиля PEP 8;
  - `F` — неиспользуемые импорты и переменные;
  - `I` — автоматическая сортировка импортов;
  - `UP` — обновление синтаксиса под современные версии Python;
  - `B` — выявление потенциальных багов и антипаттернов;
  - `SIM` — упрощение сложных конструкций.
- **Контроль типов through basedpyright:**
  - Режим `typeCheckingMode = "standard"`;
  - 100% аннотация типов всех входных параметров и возвращаемых значений;
  - Использование стандартных дженериков Python 3.13: `list[str]`, `dict[str, Any]`, `X | None`.
- **Безопасность и локальность по 152-ФЗ:**
  - Запрещено добавление внешних сетевых вызовов при обработке документов;
  - Запрещено сохранение данных документов в локальные базы данных.
